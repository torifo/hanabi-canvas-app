# 気配の火花（リモート火花）の奥行き設計書

作成日: 2026-09-10　担当: Fable 5（graphics / ui）

## 背景

タップ火花は送信側のシーン座標（1440×810）をそのまま受信側の着弾位置に使っている。本番で実測したところ通信は双方向とも正常だが、スマホ縦では cover クロップで **x 533–907（横幅の26%）しか見えない**ため、PC の左右74%のタップは画面外へ着弾し、帯の中でも縦積みの三輪に当たるとパルスだけで火花が出ない。さらにリモート火花は粒31個・寿命半分・閃光なしと控えめで、届いても気づけない。

「同じ場所に着弾する」という前提は、メッセージ花火の設計（座標を送らず各端末が自分の空へ置く）と既に食い違っている。**位置が端末ごとに違うことを仕様として認め、それを「遠くの空から届いた気配」として奥行きで表現する**方向へ改める。

## 体験の流れ

自分がタップすると、手前で明るい火花が散り、最寄りの大輪がパルスする（変更なし）。

少し間をおいて、誰かの火花が **自分の空の同じあたり（左寄り・右寄り、高い・低い）** に、小さく、やや遅れて、手前の輪の向こう側で散る。自分の火花より小さく淡く、動きがゆっくりで、閃光の代わりに遠い光のにじみが一瞬だけ広がる。同じ位置ではなく「向こうの空にも上がった」と感じられる。

## 決定事項

### プロトコルは変えない

`SparkMessage { type: 'spark', x, y }` の形と、x, y がシーン座標系 0–1 であることは維持する。サーバーとクライアントの契約 D1 は「受信側の解釈」だけを改める（[design.md](design.md) の D1 を参照）。

### 位置は自端末の可視空へ射影する

受信した (x, y) を、送信側の座標としてではなく **「シーン全体に対する相対位置」** として扱い、自端末の可視範囲へ線形に射影する。

```
view = visibleScene()            // cover クロップで見えているシーン範囲
m    = 48                        // 端に張り付かないための内側マージン (scene px)
sx   = view.minX + m + x * (view.maxX - view.minX - 2m)
sy   = view.minY + m + y * (view.maxY - view.minY - 2m)
```

- PC 横（16:9）: 可視範囲＝シーン全体なので、マージン分を除きほぼ恒等変換。従来の見え方を保つ
- スマホ縦: x が 533–907 の帯に圧縮される。PC 左端のタップは帯の左端、右端は帯の右端に届く
- 横長すぎる画面（21:9 など）: y が圧縮される。左右方向と同じ扱い

これで「左のほうで誰かが触れた」という相対情報は残り、画面外に消えることはなくなる。

### 常駐の輪に重なったら外へ逃がす

射影後の点が常駐の輪（`cloudAt` の判定半径 `R × 1.12`）の内側なら、輪の中心から見た同じ方向へ **`R × 1.28`** の距離まで押し出す。押し出し先が可視範囲を出る場合は反対方向へ押し出す。輪のパルスは従来どおり起こす（触れられた輪が応える、という現行の意味を残す）。

縦画面は帯の大部分を三輪が占めるため、押し出し後が別の輪に入ることがある。その場合は最大2回まで繰り返し、それでも入るなら **帯の中で三輪から最も遠い点**（メッセージ花火と同じ「候補点を撒いて最遠を選ぶ」手順、候補12個）に置く。

### 奥行きの表現

リモート火花は **遠景層** として描く。手前（自分）と遠景（誰か）を次の要素で分ける。

| 要素 | 自分の火花（手前） | 気配の火花（遠景） |
| --- | --- | --- |
| 粒の数 | `140 × intensity` | `140 × 0.30` ≒ 42（現行31から微増） |
| 粒の大きさ | 1.0 | 0.6 |
| 初速 | `v0` | `v0 × 0.7`（遠いものは遅く見える） |
| 重力 | 0.022 | 0.016 |
| 寿命 | 1.0 | 0.85（現行0.5から回復。小さいぶん長めに残す） |
| 不透明度の上限 | 1.0 | 0.7 |
| 色 | シェル色そのまま | シェル色を **`SCENE_PALETTE.sky` 側へ 25% 寄せる**（大気遠近） |
| 閃光 | あり（`flashes`） | なし。代わりに半径 `90` の淡いにじみ（alpha 0.18 → 0 を 420ms） |
| 描画順 | メッセージ花火・常駐輪より **後**（手前） | メッセージ花火・常駐輪より **前**（向こう側） |
| 遅延 | なし | 受信から **240–420ms** のランダム遅延の後に開く |
| 音 | 自分のタップ音 | なし（変更なし） |

遅延は「遠くの音が遅れて届く」の視覚版で、自分の火花と同時に見えることを避け、通信の揺らぎも隠す。遅延中は何も描かない（打ち上げ軌跡は付けない。タップ火花は「昇らない」のが現行の世界観）。

描画順を変えるため、`stars` を `nearStars`（自分）と `farStars`（気配）に分ける。粒の物理は同じ関数で処理し、重力と減衰の係数だけ層で切り替える。

### 遠景層の共通ルール（メッセージ花火と共有）

奥行きを持たせると、遠景へ退いた花火には触れられなくなる。これは受け入れる。代わりに次を守る。

- **遠景の花火の文字は読めない。** ホバー・タップのどちらでも文面を出さない。ラベルと「消す」は手前層（`near > 0.6`）だけに描く
- **遠景の花火は消せない。** 消したい花火は手前にいる間に消す。遠景へ退いた後は「今夜の積み重なり」として光だけが残り、正午の掃除で消える
- 気配の火花はそもそも文字を持たないので、遠景に置いても読める・消せるの問題は起きない

現行の `messageAt` / `dismissAt` / ラベル描画はいずれも `near > 0.6` で判定しており、この要件を既に満たしている。実装時はこの閾値を遠景層の定義として `FAR_THRESHOLD` に名前を付け、三箇所で共有する。

### ムードとの関係

- 高鳴り: 上記どおり
- 静けさ: 自分の打ち上げが無いため、届くのは気配だけ。現行どおり `SPARK_SHELLS.quiet` の色で、遠景の扱いも同じ。静けさモードは鑑賞専用なので **受信は止めない**（意図的、既存決定）

### 注釈

位置が端末ごとに違うことを、カウントダウン（花火大会の日程）の **上** に一行で出す。

```html
<aside class="countdown" aria-live="polite">
  <p class="countdown__note">誰かの気配は、画面の大きさに合わせて届く場所が変わります</p>
  <p class="countdown__label">次の花火まで</p>
  ...
```

- 文言は暫定。「ズレる」「バグ」を連想させる語は使わず、仕様であることが伝わる言い回しにする
- 見た目は `.countdown__source` と同じ（明朝ではなくゴシック、0.56rem、`--muted`、opacity 0.7）。`.countdown__label` との間に `margin-block-end: 0.5rem`
- `aria-live` 領域の中だが静的テキストなので読み上げの邪魔にはならない。`countdown__time` の更新時に再読されないよう、`aria-live` は時間の `<p>` 側へ移す（現状は `<aside>` 全体）
- 気配トグルを OFF にしたときは非表示にする（気配を受け取らないなら意味がないため）。`UIController.onPresenceToggle` で `hidden` を切り替える

### 契約の変更（design.md D1）

「全端末で火花が同じ『場所』に着弾する」を次に置き換える。

> 受信側の GraphicsEngine は、受信した (x, y) をシーン全体に対する相対位置として **自端末の可視範囲へ射影**し、常駐の輪と重なる場合は輪の外へ逃がして遠景層に描く。同じ位置に着弾することは保証しない。

## テスト

`src/graphics/remoteSpark.test.ts`（vitest、DOM 不要）

- 横 16:9 の可視範囲では射影がマージン分を除き恒等になる
- 縦 390×844 の可視範囲では x=0.1 / x=0.9 がともに 533–907 の内側に入る
- 21:9 では y が圧縮され可視範囲内に収まる
- 輪の内側の点は中心から同じ方向へ `R × 1.28` に押し出される
- 押し出し先が可視範囲外なら反対方向へ出る
- 2回押し出しても別の輪に入る配置では、三輪から最も遠い点が返り、どの輪の判定半径にも入らない

`GraphicsEngine` 本体は Canvas 依存のため、既存どおり CDP スクリーンショットで目視確認する（`scratchpad/repro.js` を `scripts/verify-presence.mjs` として整備し、PC 横→スマホ縦の着弾がスクリーンショット上で確認できる状態にする）。

## 変更しないもの

- `SparkMessage` の形、座標系、サーバーの検証・レート制限
- 自分のタップ火花の見え方（粒数・閃光・輪のパルス・音）
- メッセージ花火の配置・遠景への退き方
- 静けさモードが鑑賞専用であること

## 後で調整する

- 遠景の係数（粒数 0.30 / 大きさ 0.6 / 初速 0.7 / 遅延 240–420ms）は実機で並べて見ながら詰める
- 注釈の文言と、スマホでカウントダウンの上に一行増えたときの余白
- 大気遠近の色寄せ 25% は、静けさモードの青緑シェルで濁らないか確認する
