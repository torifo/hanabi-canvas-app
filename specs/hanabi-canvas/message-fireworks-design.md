# メッセージ花火 設計書

作成日: 2026-07-26　担当: Fable 5（graphics / ui）＋ Terra（protocol / server）

## 背景

現在の「気配」は座標だけを運ぶ火花で、1.5秒ほどで消える。触れて灯す手触りはあるが、**灯したものに中身がない**。ここに短いメッセージを載せ、空に咲いた花火へ触れると読める仕組みを足す。

いいね・フォロワー・ランキングを持たないという製品の前提は変えない。メッセージは誰が書いたか分からず、サーバーにも残らない。既存のUI・操作（タップ火花、長押しチャージ、大輪のホバー、ムード切替、カウントダウン）は一切変更せず、**追加のみ**で構成する。

## 体験の流れ

橋のたもとに、打ち上げ前の玉が控えめに置かれている。ホバーするとわずかに浮いて応え、クリックすると入力欄が静かに開く。言葉を込めて放つと玉が昇って開花し、同時に他の人の空へも届く。

空に咲いた花火へホバーすると、その傍らに文面が明朝体で浮かぶ。読んでいる間、その輪は減衰を止める。

## 決定事項

### 座標を送らない

メッセージ花火の位置はユーザーが選ばず全自動で決まる。位置に利用者の意図が乗らない以上、**座標は通信に含めない**。各端末が受信した時点で、自分の空の空いている場所へ咲かせる。

この判断により3つの問題が同時に消える。

- 縦画面では見える範囲が x 533–907 に狭まるため、横画面で置かれた座標は画面外になりうる問題
- 端末ごとに持っている花火の数が違うため、送信元で重ならなくても受信側では重なる問題
- 通信量（座標2つ分の余裕が文面へ回る）

重なり判定は本質的に端末ごとのローカルな問題であり、各端末が自分の空を自分で構成するのが正しい。

### プロトコル

```ts
interface BloomMessage {
  type: 'bloom';
  text: string; // 正規化後 30 文字以内
}
```

30文字の日本語は UTF-8 で約90バイト、JSON全体で約115バイト。**サーバーの既存の受信上限256バイト・10メッセージ/秒の制限は変更不要**。連投を許容する方針とも整合する。

サーバー側の変更は、`type: 'bloom'` を検証して中継対象に加えることのみ。DBも識別情報も持たない現在の性質は変わらない。

### 色の導出

色はメッセージに含めない。**同じ文面からは必ず同じ色が導かれる純関数**を各端末が持つため、送らなくても全員の空で同じ色に咲く。

1. 単語群による決定 — 文面に特定の語が含まれれば対応する色調を選ぶ（例: 祝い・おめでとう・ありがとう → 金、静か・眠る・雨 → 青緑、好き・恋 → 桃、明日・頑張 → 橙）
2. 該当がなければ文面のハッシュから色相を導く

いずれの場合も、コアは既存の輝度設計に従って `#FFF6E0` 系へ脱彩し、色は減衰部で表現する。純彩色のコアは Bloom 閾値に届かないため使わない。

### 配置アルゴリズム

シーン空間は 1440×810、水平線 y=421、橋のデッキ y=560。空として使える帯は **y 70–380**。ここに常駐の三輪（半径178・178・86）が居るため、空きは約24万px²。メッセージ花火を半径64で描くと余白込み1発あたり約1.8万px²、**気持ちよく置ける上限は横画面で12発・縦画面で6発**。

新しい1発を置くとき、候補点を24個ランダムに撒き、次のすべてから**最も遠い点**を選ぶ。

- 常駐の三輪
- 既存のメッセージ花火（手前層）
- UIの占有域

UI要素（ブランド・ムードピル・気配・カウントダウン）はビューポート基準で配置されるため、シーン空間での占有域は画面比率によって変わる。配置のたびに各要素の矩形を取得し、`toSceneCoords` の逆変換でシーン座標へ投影してから避ける。固定値で持たない。

格子配置より自然な散らばりになり、空きがある限り必ず離れる。

縦画面では可視帯 x 533–907 に限定して同じ手順を行う。画面の向きが変わったときは、手前層を新しい可視帯へ再配置する。

### 古い花火の扱い

手前層の上限を超えると、いちばん古いものが**小さく淡い遠景の光へ退く**。文面は読めなくなるが、今夜の積み重なりは空に残る。遠景では重なっても奥行きに見えるため破綻しない。

この挙動は使いながら調整する前提とし、退き方（速度・最終的な大きさ・遠景の上限）は実装後のフィードバックで詰める。

### 保存と正午リセット

受け取った花火は端末の localStorage に保存する。サーバーは何も覚えない。

- 保存キー: `hanabi.messages.v1`
- レコード: `{ id, text, at, mine, dismissed }`（位置は保存しない。起動のたびに自分の空へ配置し直す）
- **端末のローカル時刻の12:00を境に、それ以前のレコードを捨てる**。起動時に直近の正午を求めて古いものを落とし、次の正午に発火するタイマーでも実行する
- 上限60件。超えたら古い順に捨てる
- localStorage が使えない環境では、セッション中のメモリだけで動作する

### 要らない言葉への構え

送信前にクライアントで軽く弾く。

- 文字数上限（30文字）
- URL・制御文字の拒否
- 小さなNG語リスト

**連投は制限しない**。サーバーの既存レート制限（10メッセージ/秒）が最終的な安全弁として残る。

受け取った側は、その花火だけを自分の空から黙らせられる（レコードに `dismissed` を立てる）。報告はサーバーへ送らず端末内で完結する。

## モジュール構成

新規ファイルを中心に構成し、既存ファイルへの追加は最小限に留める。

| ファイル | 役割 | 依存 |
|---|---|---|
| `src/messages/messageColor.ts` | 文面 → 色。単語群で決定し、該当なければハッシュから導出 | なし（純関数） |
| `src/messages/messageGuard.ts` | 送信前の検証と正規化 | なし（純関数） |
| `src/messages/MessageStore.ts` | localStorage 保存・正午リセット・上限・個別ミュート | なし（時刻は注入） |
| `src/messages/placement.ts` | 空き場所の探索（候補点サンプリング） | なし（純関数） |
| `src/ui/ComposeOverlay.ts` | 玉から開く入力欄 | messageGuard |
| `src/graphics/GraphicsEngine.ts` へ追加 | 玉の描画とホバー、メッセージ輪の描画、文面表示、遠景層 | placement, messageColor |
| `src/main.ts` へ追加 | 玉のクリック → 入力 → 送信・保存・開花の配線 | すべて |
| `server/server.js` へ追加 | `type: 'bloom'` の検証と中継 | なし |

上4つは純関数・純ロジックのため、既存の `lifecycle.ts` と同じく node 環境のテストで担保できる。

### 契約の追加

`src/types.ts` に以下を加える。既存の契約は変更しない。

```ts
interface BloomMessage { type: 'bloom'; text: string; }

interface MessageRecord {
  id: string;
  text: string;
  at: number;      // epoch ms
  mine: boolean;
  dismissed?: boolean;
}
```

`PresenceClient` に `sendBloom(text)` と `onRemoteBloom(cb)` を追加する。既存の `sendSpark` / `onRemoteSpark` はそのまま残す。

## エラー処理

- **検証で弾かれた文面**: 赤いエラーを出さず、入力欄が送信を受け付けないだけに留める（世界観を壊さない）
- **通信が繋がっていない**: 自分の空にだけ花火が上がり、保存される。他の人には届かないが体験は止まらない
- **localStorage が満杯・無効**: 保存を諦め、セッション中のメモリのみで動作する
- **不正な受信メッセージ**: 既存方針どおり黙って破棄する
- **空きが見つからない**: 最も遠い候補点をそのまま使う（多少重なっても描画は破綻しない）

## テスト

node 環境で純関数・純ロジックを担保する。

- `messageColor`: 決定性（同じ文面 → 同じ色）、単語群の一致、フォールバック
- `messageGuard`: 文字数上限、URL、制御文字、NG語、正規化（前後空白・改行）
- `MessageStore`: 正午境界のリセット、上限超過時の破棄、dismissed の復元、localStorage 不在時の縮退
- `placement`: 既存の占有域から離れた点を選ぶこと、空きがない場合も点を返すこと
- `server`: `type: 'bloom'` の中継、文字数超過・不正型の破棄

描画とUIは既存方針どおり手動確認とする。

## 変更しないもの

- タップ火花・長押しチャージ・大輪のホバーとパルス
- ムード切替、カウントダウン、イントロ遷移
- `SparkMessage` の形と既存の送受信
- サーバーの256バイト上限・10メッセージ/秒・DBなし・識別情報なし
- 既存のUI要素の見た目と配置

## 後で調整する

- 古い花火の退き方（速度・最終的な大きさ・遠景層の上限）
- 手前層の上限（横12・縦6は算出値であり、実際の見え方で調整する）
- 単語群と色の対応表の充実
